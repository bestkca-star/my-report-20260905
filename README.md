# 방문검진 심사유의 분석

**방문검진(출장 건강검진) 결과의 심사유의 판정을 분석해, 검진 프로세스와 판정 운영의
개선 지점을 찾는 Streamlit 앱입니다.**

> 데이터는 전부 **합성**입니다. 실제 보험사 데이터는 쓰지 않았습니다.
> 시드를 고정해 만들었으므로 누가 받아도 같은 숫자가 나옵니다.

모두의연구소 8주차 실습 — 「데이터를 거부하고, 세고, 감추고, 문장으로 내보내는 앱」

---

## 시작

```bash
pip install -r requirements.txt
streamlit run app.py
```

---

## 이 앱이 하는 일

앱이 판단하지 않습니다. **판단할 재료를 놓고, 사람이 판단한 것을 기록합니다.**
그 자리가 게이트 셋입니다.

| 화면 | 무엇 |
|---|---|
| **실행** | 데이터를 넣고 검증 4건을 돌린다 → **게이트 1**(입구) |
| **대시보드** | 퍼널·분해·전후 비교·판정 카드 → **게이트 2**(출구) |
| **리포트** | 8장 문서를 만들고 PDF로 내보낸다 → **게이트 3**(발송) |
| **아카이브** | 실행 이력과 게이트 통과 근거 |

### 게이트가 하는 일

게이트는 **버튼이 아니라 기록**입니다. 통과시키려면 근거를 적어야 하고,
그 근거가 아카이브에 남습니다. 근거를 안 적으면 앱이 반쪽이 됩니다.

---

## 이 앱이 하지 않는 일

| 안 하는 것 | 왜 |
|---|---|
| **못 믿을 값을 계산하지 않는다** | 계산해 놓고 화면에서 빼는 것과 다릅니다. 값이 변수에 남아 있으면 리포트·로그로 새어 나갑니다 |
| **인과를 주장하지 않는다** | 관측 데이터입니다. "A가 낮은 구간에서 B도 낮다"까지가 사실이고 "A 때문에 B가 낮다"는 주장입니다 |
| **해석과 제안을 자동으로 쓰지 않는다** | 자동화하는 순간 책임의 주체가 사라집니다. 안 쓰면 문서에 "(작성되지 않음)"이 그대로 찍힙니다 |

## 무엇을 하나로 세는가

**검진 건 1회**입니다. 식별자는 `검진건ID` 이고 `nunique` 로 셉니다.

행으로 세면 안 됩니다 — 이벤트 표에 완전중복 188행(2.9%)이 있어 분모가 부풉니다.
사람(`피검자ID`)으로 세도 안 됩니다 — 지금은 값이 같지만 재검이 생기면 갈라집니다.

## 퍼널

| 단계 | 도달 | 전 단계 대비 |
|---|---:|---:|
| 검진의뢰접수 | 2,004 | — |
| 방문예약확정 | 1,794 | 89.52% |

| **결과전항목수신** | **957** | **62.75%** ← 병목 |

## 지표

| | 지표 | 계산식 | 값 |
|---|---|---|---|
| 주지표 | 심사유의율 | 심사유의 건 ÷ 결과 수신 건 | **36.15%** |
| 가드레일① | 경계선 비율 | 경계선 건 ÷ **심사유의 건** | 22.83% |
| 가드레일② | 재작업률 | 90일 내 재검 ÷ **관측 창이 닫힌 건** | 9.94% |

재작업률은 이름이 "이탈률"이 아닙니다. **부호가 반대**라서입니다 — 검진에서 재검은
나쁜 신호이므로, 여기 남는 것이 좋은 것입니다.

## 유효 구간은 지표마다 다릅니다

| 지표 | 구간 | 왜 거기서 잘리나 |
|---|---|---|
| 퍼널 전환율 | ~ 2026-08-16 | 의뢰→수신 최대 34일. 그보다 최근 건은 갈 시간이 없다 |
| 심사유의율 | ~ 2026-09-19 | 수신 시점에 판정이 확정된다. 자르지 않는다 |
| 재작업률 | ~ 2026-06-21 | 재검 관측 창이 90일이다 |

## 무엇이 감춰지는가

표본이 최소 기준(200건)에 못 미치는 칸은 **전환율을 계산하지 않습니다.**
사유와 표본 수만 남고, 그 사실이 리포트의 한계 절로 그대로 넘어갑니다.

- 검진기관으로 쪼개면 8칸 중 **6칸**이 감춰집니다
- 연령대로 쪼개면 5칸 중 **2칸**
- 분기 비교 4장 중 **1장**이 무효 (2025Q3 수신 25건)

대시보드에서 분해 축을 바꿔 보면 실제로 값이 사라지는 것을 볼 수 있습니다.
